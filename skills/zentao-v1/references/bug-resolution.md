# Bug 处理规则

## 修复门禁

只有以下两种情况允许进入 `resolution=fixed`：

1. 本次成功复现、确认根因、完成代码或配置修复，并通过回归验证。
2. 已有改动可追溯，解决版本准确，且有回归证据并得到用户确认。

仅凭禅道状态 `active` 或用户说“已经好了”不能解决 Bug。未满足门禁时不得调用 `resolveBug`，也不得为了关闭 Bug 制造代码改动。

## 工具分工

- `getBugDetail`：读取并核对 Bug 详情。
- `updateBug`：更新 Bug 属性；先读取当前对象，保留未修改的必填字段，不能用部分对象覆盖整条记录。
- `resolveBug`：写入解决方案、解决版本、指派人和备注；解决版本默认使用真实的 `trunk`，不得猜版本。

## 解决备注

必须使用三行格式，不能插空行：

```text
产生原因：<可验证的技术或业务根因>
解决方案：<本次实际执行的修复方案>
改进措施：-
```

## 回退和回读

- 新 MCP 优先调用 REST v1；只有明确路由不兼容时才由适配器回退 Legacy。
- 写请求超时、连接中断或响应不明确时，先读取目标状态，禁止立即重试。
- 写入后至少回读状态、解决方案、解决版本、执行人、日期和最新备注。
- REST v1、Legacy 均失败时报告能力缺口，不切换到其他禅道 MCP。
