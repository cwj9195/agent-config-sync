# 公司工作流

以公司已有业务决策、项目范围和当前系统事实为依据，协助处理 ZenTao 工作项与 YApi 接口契约。先识别用户要求的工作范围和目标系统，再按该系统规则操作；不要仅因同一需求提到两个系统，就擅自同时写入两边。

## 路由

- **ZenTao 工作项**：任务、需求、Bug、测试用例等读取或写入，先读取本技能内的 [ZenTao MCP 工作流](references/zentao-mcp.md)，再按需读取 [禅道详细规则](references/zentao/) 中对应主题；不需要加载另一个 ZenTao 技能。
- **YApi 接口契约**：读取、检索、创建或更新 API 定义，以及契约到前端请求类型的衔接，读取 [YApi MCP 工作流](references/yapi-mcp.md)。
- **跨系统工作**：分别确认两边的目标 ID、项目和状态。ZenTao 中有关联接口或 Bug，不代表已经授权修改 YApi、代码或测试数据；只执行用户要求的写入。

## MCP 不可用时的处理

- 执行前依据当前工具清单确认该操作依赖的 MCP 和工具。若目标 MCP 未提供、工具不存在或调用失败，明确报告缺失的 MCP/工具及受影响的操作；暂停依赖该外部系统的查询和写入。
- 继续不依赖该 MCP 的本地工作，例如整理用户给定材料、检查本地文件或起草待审阅内容；清楚标注未做实时查询、未写入，不能把草案表述为系统现状。
- 不自动改用其他 MCP、HTTP/CLI、浏览器页面模拟或未记录的接口绕过技能规定。只有用户明确要求且适用规则允许时，才按指定方式继续。
- 写入后若 MCP 调用结果不明，优先用同一 MCP 回读确认；若该 MCP 仍不可用，不盲目重试，也不宣称成功，报告结果待核实。

## 公司工作范围与事实边界

- 使用当前 MCP 连接可见的项目和账号；项目、分类、需求字段、API 路径和后端规则都要实时核实，不凭项目名或历史记忆猜测。
- 区分用户明确要求、已批准的 PRD/接口契约、当前代码行为、YApi 文档和真实后端验证。代码现状或旧 YApi 定义可以作为证据，不能自动升级成产品决定或后端承诺。
- 关键信息缺失会改变 API 请求/响应、影响范围或工作项归属时，先展示已查事实和待定选项并询问；不要为使流程顺利而发明字段、枚举、状态或责任人。
- 不在技能内容、脚本、日志或回复中输出账号凭据、Token、Cookie、完整认证头等敏感信息。

## 写入与完成判断

- 读取和核对可以直接进行。用户明确要求创建或更新目标记录时，按对应技能规则准备并执行，不重复索要已给出的授权。
- 如果写入内容取决于未确认的业务语义，先停在可审阅的契约草案或字段清单，取得用户决策后再写。
- 写入后通过对应 MCP 重新读取，核验实际落库字段；把“已保存”“已回读”“Mock 可运行”“后端已联调”分开报告。
- 写入超时或结果不明时先回读，确认记录是否存在/更新后再决定下一步；不得盲目重试。
